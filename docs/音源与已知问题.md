## 音源实测状态（2026-09-18）

口径：`cargo test --release resolves_live -- --ignored` 解析真实播放地址；
下载一列来自 `src-tauri/tests/live_download.rs`，走 `fetch_audio` 真实字节通道。
匿名访问，未配置任何平台 Cookie。

| 音源 | 搜索 | 解析 | 下载 | 说明 |
|---|---|---|---|---|
| netease | 通过 | 通过 | 8.41 MB | 搜索层按 `privilege.fl > 0` 过滤不可播放曲目 |
| kugou | 通过 | 通过 | 2.59 MB | 不按 `Privilege` 过滤：实测 `5` 也可解析，该字段只用于选 hash 层级 |
| qq | 通过 | 通过 | 4.14 MB | 搜索层按 `pay.payplay != 1` 过滤付费曲目；免费曲约 1/6 才返回 vkey |
| bilibili | 通过 | 通过 | 7.91 MB | 需 `buvid3` cookie + `wbi/view` 端点，见下 |
| migu | 通过 | 通过 | 未测 | |
| fivesing | 通过 | 通过 | 未测 | |
| jamendo | 通过 | 通过 | 未测 | |
| qianqian | 通过 | 失败 | - | `tracklink` 对匿名请求各档 `path` 与 `trail_audio_info.path` 全空 |
| kuwo | 通过 | 失败 | - | `mobi.kuwo.cn` 返回 `code:407` 地域封锁，降级端点返回 `The request is illegal!` |
| soda | 失败 | 失败 | - | `track_v2` 已下线；`seo_track` 兜底仅 60 秒试听 |
| joox | 通过 | 失败 | - | `web_get_songinfo` 对真实 songid 返回 404 零字节，且 songid 已改为 base64 |
| apple | 失败 | 失败 | - | 首页脚本取不到 catalog token |

除 bilibili 外的 5 个失败源，失败均来自平台接口本身（上游变更或地域封锁），不是 adapter 缺陷。

实现说明：

- 下载只在用户选定的音源上解析，不做跨源自动回退；换源是独立的用户动作。
- `music.91q.com` 强制 gzip 响应，故 reqwest 启用 `gzip` feature。
- kugou / 网易等按客户端 IP 限流的端点补随机国内 IP 头。
- bilibili 匿名访问需要两项处理，否则完全不可用：
  1. 请求补 `buvid3` cookie，缺失时 `api.bilibili.com` 一律 412。实测该 cookie
     只校验存在性，故用固定占位值，省掉每次调用的首页往返。
  2. 详情端点改用 `x/web-interface/wbi/view`：无前缀的 `x/web-interface/view`
     已对任意 cookie 与表头组合恒返回 412，`wbi/` 路由返回同样载荷且不需签名参数。
- soda 加密流返回 `SOURCE_PLAYBACK_ENCRYPTED`，不把密文 URL 交给 WebView；`play_auth` 解密交付未实现。
- Apple Music 只解析官方 HTTP preview；完整音频（`enhancedHls`）受 DRM 保护，不纳入普通播放解析。

### AI 接入（MCP + CLI）与日志

- 依赖 Aether（git 依赖固定在 `73fcda9`，npm 用 `github:ouraihub/Aether#<commit>&path:packages/ui`，
  做法同 AutoNote；构建不需要同级目录）：`aether-observability`（滚动文件日志）、`aether-mcp-server` +
  `tauri-plugin-aether`（回环 MCP 服务、令牌、作用域、设置 UI 的后端）、`@ouraihub/aether-ui`
  （`McpServerSettings`、`LogPanel`、`LogSettings`、确认对话框）。为此 `rusqlite` 0.32→0.40
  （启用 `fallible_uint`）、`tauri` 2.11→2.12.1，`@tauri-apps/api`/`cli` 同步到 2.12。
- 日志此前只写 stdout，release 无控制台，等于没有。现写 `logs/autoowl.log`（5 MB × 3）。
- MCP 工具：`search_songs`、`play_song`、`pause`、`resume`、`next`、`previous`、`player_status`；
  作用域 `music.read` / `music.control`，默认全关。播放类工具发 `mcp:player` 事件，由 `PlayerBar`
  走与点击相同的 `playerStore`，不另起播放器。`autoowl-cli` 为同一 MCP 端点的薄客户端。
- 实测：UI 启动服务并发放令牌 → `tools/list` 返回 7 个工具 → CLI `search 千千阙歌` 返回 10 条 →
  `play 1` 后 `<audio>` 推进到 3.4 s → `status` 为 playing → `pause` 后 `<audio>.paused=true` →
  撤销令牌（`revoked_at` 已写）。
- 顺带修复：`PlayerState.current` 空时序列化为 `null`，前端按 `=== undefined` 判断导致
  `PlayerBar` 抛 `Cannot read properties of null (reading 'ref')`；现空时省略字段。
