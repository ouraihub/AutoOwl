# 音乐桌面应用概要设计

## 1. 文档目的

本文档描述 AutoOwl 的整体技术架构、模块边界、核心接口、数据流、错误和日志约束，为详细设计、任务拆分和代码评审提供基线。

AutoOwl 是纯 Rust 后端的 Tauri 2 桌面应用，前端使用 Svelte 5、TypeScript、Tailwind CSS 4、shadcn-svelte 和 bits-ui。

## 2. 设计目标与范围

### 2.1 目标

- 完整的用户流程：多平台搜索、试听、下载、歌词、封面、播放器、歌单、专辑、本地音乐和登录配置。
- 采用接口优先、组合优先和模块化设计，隔离音乐平台和系统能力变化。
- 让 Rust 业务逻辑可独立测试，让前端通过类型化契约访问后端。
- 让下载、扫描和登录等长任务具备进度、取消、失败和恢复状态。
- 首发优先保证 Windows 桌面体验；业务能力一次覆盖完整，不以单平台 MVP 作为产品目标。

### 2.2 首发范围

- 多平台歌曲、歌单、专辑搜索和链接解析
- 歌曲详情、试听地址、歌词、封面和音质信息
- 单曲与批量下载、下载进度、取消、失败重试和下载记录
- 全局播放器、播放历史、队列和媒体控制
- 本地歌单、歌单分类、我的歌单和外部歌单导入
- 本地音乐扫描、分页、元数据、封面、歌词、上传、删除和搜索
- Cookie 配置、登录状态和平台扫码登录入口
- 基础设置、下载目录、文件名模板、日志和 FFmpeg/ffprobe 集成
- Windows Tauri 打包

### 2.3 非首发范围

首发平台和能力以已实现并可验证的 source adapter 为基线。Android、macOS/Linux、TUI、Web 独立部署和视频生成为后续发行形态或独立目标。

└──────────────────┬─────────────────────┘

## 5. 模块设计

### 5.1 Search

职责：接收关键词和查询选项，调用音乐源适配器，规范化为统一的歌曲结果。

输入包括关键词、搜索类型、分页和音质偏好；输出为 `SearchResult`。不向前端泄露平台私有响应结构。

### 5.2 Music Source

每个音乐源实现 `MusicSource` trait，负责搜索、详情、播放资源、歌词、封面和必要的链接解析。

```rust
#[async_trait]
pub trait MusicSource: Send + Sync {
    fn id(&self) -> SourceId;
    fn capabilities(&self) -> SourceCapabilities;
    async fn search(&self, query: SearchQuery) -> Result<SearchResult, SourceError>;
    async fn detail(&self, song: SongRef) -> Result<Song, SourceError>;
    async fn resolve(&self, song: SongRef) -> Result<PlayableResource, SourceError>;
    async fn lyrics(&self, song: SongRef) -> Result<Option<Lyrics>, SourceError>;
    async fn cover(&self, song: SongRef) -> Result<Option<CoverResource>, SourceError>;
}
```

平台适配器不得直接修改 UI 状态；平台错误必须转换为统一的 `SourceError`。

### 5.3 Player

职责：维护当前歌曲、队列、播放模式、音量、进度和播放状态。播放器状态由 Rust 作为事实来源，前端 store 只保存展示状态。

```text
PlayerState: idle | loading | playing | paused | ended | failed
```

播放失败时记录原因，并由 application 层决定是否允许换源或重试。

### 5.4 Download

职责：创建和维护下载任务，处理资源解析、文件写入、取消、重试、文件名、重名和可选媒体处理。

```rust
trait DownloadService {
    async fn create(&self, request: DownloadRequest) -> Result<DownloadTask, AppError>;
    async fn cancel(&self, task_id: TaskId) -> Result<(), AppError>;
    async fn get(&self, task_id: TaskId) -> Result<DownloadTask, AppError>;
    async fn retry(&self, task_id: TaskId) -> Result<DownloadTask, AppError>;
    async fn list(&self) -> Result<Vec<DownloadTask>, AppError>;
}
```

下载事实状态保存在 Rust task registry，并按需持久化；前端通过 `download:changed` 事件更新显示。

下载状态机：

```text
queued -> resolving -> downloading -> processing -> completed
   |          |             |             |
   +------> cancelled <------+-------------+
              ^
              |
        cancel_requested

queued/resolving/downloading/processing/failed -> retry
```

失败状态必须包含错误码。取消和失败时清理临时文件；目标文件使用临时文件完成后原子移动，禁止直接覆盖写入。

### 5.5 Settings and Storage

职责：管理下载目录、文件名模板、音质偏好、日志级别和播放器设置。首发统一使用版本化 SQLite schema，并由迁移程序管理版本。

应用使用独立数据目录，不读取、不修改其它程序的数据库、配置或下载目录。

### 5.6 Media Tools

通过 `MediaTool` trait 封装 FFmpeg/ffprobe，不允许 domain 直接启动外部进程。

```rust
trait MediaTool {
    async fn probe(&self, path: &Path) -> Result<MediaMetadata, MediaToolError>;
    async fn embed_metadata(&self, request: EmbedRequest) -> Result<(), MediaToolError>;
}
```

缺少 FFmpeg 时应返回可识别的降级错误，不影响基础搜索和下载流程。

### 5.7 Auth and Credentials

职责：管理多平台 Cookie、登录状态和扫码登录流程。每个平台通过 `CredentialStore` 和 `QrLoginAdapter` 隔离，前端只能获取脱敏状态和二维码会话状态，不能读取无必要的 Cookie 原文。

```rust
trait CredentialStore {
    async fn get_status(&self, source: SourceId) -> Result<AuthStatus, AppError>;
    async fn save_cookie(&self, source: SourceId, cookie: SensitiveString) -> Result<(), AppError>;
    async fn clear_cookie(&self, source: SourceId) -> Result<(), AppError>;
}
```

## 6. 核心领域模型

```text
SourceId = string
SongRef { source: SourceId, scope: string, site_id: string }
Artist { id?: string, name: string }
Song { ref, title: string, artists: Artist[], album?: AlbumRef,
       duration_ms?: number, cover?: CoverResource }
PlayableResource { url: string, expires_at?: string, quality: AudioQuality,
                   headers?: Record<string, string> }
Lyrics { original?: string, translated?: string, romanized?: string,
         timed_lines?: TimedLine[] }
DownloadTask { id, song, target, state, progress, error?: AppError }
AppSettings { download_dir: string, filename_template: string,
              preferred_quality: AudioQuality }
```

跨 Tauri 边界统一使用 `camelCase` JSON DTO；Rust 内部可使用 `snake_case`，由序列化层显式转换。时长统一使用毫秒，时间统一使用 RFC 3339 字符串。

站点身份使用 `source + scope + site_id`，避免不同平台的相同数字 ID 冲突。

## 7. Tauri 边界契约

### 7.1 Command

Command 只负责参数校验、鉴权/权限检查、调用 application use case 和返回 DTO，不承载业务编排。

首发 command：

```text
search_songs
get_song_detail
resolve_playback
get_lyrics
create_download
cancel_download
get_download_task
get_settings
update_settings
choose_download_directory
```

Command DTO 必须集中定义。首发最小映射为：

```text
search_songs(SearchSongsInput) -> SearchResultDto
get_song_detail(GetSongDetailInput) -> SongDto
resolve_playback(ResolvePlaybackInput) -> PlayableResourceDto
get_lyrics(GetLyricsInput) -> LyricsDto
create_download(CreateDownloadInput) -> DownloadTaskDto
cancel_download(TaskIdInput) -> EmptyResult
retry_download(TaskIdInput) -> DownloadTaskDto
get_download_task(TaskIdInput) -> DownloadTaskDto
list_download_tasks(EmptyInput) -> DownloadTaskDto[]
```

命名采用 `verb_noun`，输入输出为显式 DTO。长任务 command 立即返回任务对象，不阻塞 WebView。

### 7.2 Event

事件只用于后端主动推送的状态变化，集中定义名称、payload 和版本。

```text
download:changed
player:changed
operation:progress
operation:failed
```

前端 service 必须支持订阅取消，重复初始化不得重复注册监听器；页面重新进入时通过 query command 补齐当前事实状态。

## 8. 前端设计

```text
routes/
├── +page.svelte              # 搜索首页
├── player/                   # 播放相关页面/面板
├── downloads/                # 下载任务
└── settings/                 # 设置

lib/components/music/
├── SearchBar.svelte
├── SongList.svelte
├── SongRow.svelte
├── PlayerBar.svelte
└── DownloadQueue.svelte
```

页面负责组合和路由，业务组件负责交互，基础组件只负责视觉和可访问性。所有页面必须处理 loading、empty、error、retry、disabled 和窄窗口布局。

Svelte 5 使用 `$state`、`$derived` 和 `$effect`；Tauri 调用统一封装在 `lib/services`，组件不直接调用 `invoke`。

## 9. 状态和任务流

### 9.1 搜索流

```text
用户提交关键词
  -> SearchService 校验参数
  -> SearchUseCase 选择 MusicSource
  -> source.search
  -> 规范化 SearchResult
  -> command 返回 DTO
  -> 页面更新 store
```

### 9.2 下载流

```text
create_download
  -> 创建 queued task
  -> 后台任务解析资源
  -> 写入临时文件
  -> 可选 FFmpeg 处理
  -> 原子移动到目标路径
  -> completed / failed / cancelled
  -> 推送 download:changed
```

目标文件不得直接覆盖写入；取消或失败时清理临时文件。

## 10. 错误和日志设计

内部错误使用 Rust `thiserror` 保留 source chain；对外统一返回：

```ts
type AppError = {
  code: string;
  message: string;
  retryable: boolean;
  operationId: string;
};
```

前端根据 `code` 决定提示、重试、登录引导或降级，不匹配错误文本。用户可见消息与内部诊断信息分离。

Rust 使用 `tracing` 和 `tracing-subscriber`，日志包含 `operation_id`/`task_id`、模块、动作、耗时和结果。密码、Cookie、完整敏感 URL 和用户文件内容禁止写入日志。生产日志写入应用数据目录并按大小/时间滚动。

## 11. 安全与权限

- Tauri capability 遵循最小权限原则。
- 文件路径必须规范化并限制在用户选择的下载目录内。
- 下载文件名过滤路径穿越段和非法字符。
- Cookie 使用系统安全存储或受保护的应用数据，前端只获取状态，不获取无必要的原文。
- 外部链接只允许通过显式系统打开操作，禁止 WebView 任意跳转。
- 所有用户输入、远程响应和本地元数据都必须经过边界校验。

## 13. 构建和发布

开发模式使用 Vite/SvelteKit dev server 和 Tauri dev；生产模式使用 adapter-static 生成前端资源，由 Tauri 打包。Windows 首发需验证 WebView2、安装包、数据目录、日志目录和 FFmpeg 缺失时的降级行为。

## 15. 可执行补充契约

### 15.1 首发平台锁定项

详细设计开始前必须填写首发平台、是否需要 Cookie、支持的音质、搜索类型、播放资源有效期和平台错误映射。未填写前不得实现平台适配器，避免大模型自行猜测平台协议。

### 15.2 错误码

首发错误码固定为：

```text
INVALID_ARGUMENT
SOURCE_UNAVAILABLE
SOURCE_AUTH_REQUIRED
RESOURCE_NOT_FOUND
RESOURCE_EXPIRED
NETWORK_TIMEOUT
RATE_LIMITED
DOWNLOAD_CANCELLED
DOWNLOAD_FAILED
FILE_CONFLICT
FFMPEG_NOT_FOUND
PERMISSION_DENIED
INTERNAL_ERROR
```

跨 Tauri 边界只返回 `code`、安全 `message`、`retryable` 和 `operationId`；内部 source chain 仅写入日志。

### 15.3 数据库初版

首发使用 SQLite，schema 版本由迁移表管理：

```sql
CREATE TABLE app_meta (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE app_settings (
  key TEXT PRIMARY KEY,
  value_json TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE download_tasks (
  id TEXT PRIMARY KEY,
  source TEXT NOT NULL,
  scope TEXT NOT NULL,
  site_id TEXT NOT NULL,
  title TEXT NOT NULL,
  target_path TEXT NOT NULL,
  state TEXT NOT NULL,
  progress REAL NOT NULL DEFAULT 0,
  error_code TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

数据库位于应用数据目录；迁移必须幂等，失败必须回滚。任何外部数据导入必须是只读、备份、可重复和可回滚。

### 15.4 首发页面行为

| 页面/区域 | 必须行为 |
|---|---|
| 搜索页 | 输入关键词、提交、加载、空结果、错误重试、歌曲操作 |
| 歌曲行 | 显示标题/歌手/专辑/时长，支持试听、下载、歌词、封面 |
| 播放器栏 | 播放暂停、上一首/下一首、进度、音量、队列和失败提示 |
| 下载面板 | queued/running/processing/completed/failed/cancelled、进度、取消、重试 |
| 设置页 | 下载目录、文件名模板、音质偏好、日志目录和恢复默认 |

所有页面必须覆盖 loading、empty、error、retry、disabled、键盘操作、窄窗口和深色主题。

### 15.5 Tauri 权限

首发只启用窗口、事件、dialog、限定下载目录的 fs、通知和必要的外部链接能力。禁止给前端开放任意路径读写和任意命令执行。FFmpeg 由 Rust infrastructure adapter 受控启动。

### 15.6 Definition of Done

一个功能只有同时满足以下条件才算完成：

1. 有 domain/application 接口和明确 DTO。
2. 有 Rust 实现、Tauri command/event 和前端 typed service。
3. 有成功、失败、取消或重试路径。
4. 有单元测试、fixture 或集成测试。
5. 有结构化日志和稳定错误码。
6. 有页面 loading/empty/error 状态。
7. 通过 `pnpm check`、`pnpm test`、`pnpm build`、`cargo fmt --check`、`cargo clippy --all-targets --all-features -- -D warnings` 和 `cargo test`。
8. 在 Windows Tauri 开发或打包环境完成实际验收。

### 15.7 可测量验收

- 固定关键词搜索在 5 秒内返回结果或稳定错误；结果字段与 fixture 一致。
- 点击试听在 10 秒内开始播放或显示明确错误码。
- 下载任务可从 queued/running 进入 completed、failed 或 cancelled。
- 取消下载在 2 秒内进入 `cancelled`，且不继续写入目标文件。
- 同一任务不会并发写入同一目标路径。
- 网络超时、限流、用户取消映射为不同错误码。
- 关闭窗口后不残留应用启动的后台进程。
- CI 不依赖实时音乐网站；平台适配器使用固定 fixture 或 mock server。

## 16. 使用子系统与管理子系统

应用在业务上划分为两个子系统，但首发不拆分为两个应用、两个进程或两个后端服务。

### 16.1 使用子系统

- 多平台歌曲、歌单、专辑搜索和链接解析
- 播放器、播放历史和播放队列
- 单曲/批量下载、下载任务和下载记录
- 本地音乐和本地歌单
- 换源、歌词、封面和音质选择

### 16.2 管理子系统

- 系统设置、下载目录和文件名模板
- 平台 Cookie、登录状态和扫码登录
- FFmpeg/ffprobe 和媒体配置
- 日志、诊断和运行状态
- 功能开关、关于和更新

两个子系统共享 domain、application state、SQLite、日志和错误模型，通过前端路由、Tauri command 分组和权限边界隔离。未来若演进为多人服务，再拆分用户 API、管理 API 和独立管理 Web 控制台。

### 16.3 路由和命令分组

前端路由建议：

```text
/(user)/search
/(user)/playlist
/(user)/album
/(user)/local-music
/(user)/downloads
/(user)/history
/(admin)/settings
/(admin)/settings/accounts
/(admin)/settings/media
/(admin)/settings/diagnostics
```

用户命令示例：`search_songs`、`get_song_detail`、`resolve_playback`、`create_download`、`cancel_download`、`get_local_music`、`create_playlist`。

管理命令示例：`get_settings`、`update_settings`、`get_source_auth_status`、`save_source_cookie`、`start_qr_login`、`poll_qr_login`、`get_media_tool_status`、`get_diagnostics`。

管理命令必须独立校验输入、脱敏日志，并限制对 credential store、文件系统和系统能力的访问；用户页面不得直接调用管理命令。
