# Windows 发布清单

## 发布流程

1. 把 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 的版本改成同一个新版本，提交推送；可用 `pnpm exec desktop-kit version` 自查。
2. 打 tag 并推送：`git tag v<版本>`、`git push origin v<版本>`。
3. GitHub 的 `release` 工作流运行 `pnpm build:app`（先跑全部门禁），再用 `desktop-kit publish` 公开发布 Release，附两个文件（文件名不带版本号，"最新版"下载链接长期有效）：
   - `AutoOwl-windows-setup.exe`：安装版，装到当前用户，有开始菜单和卸载入口，缺 WebView2 时自动安装。
   - `AutoOwl-windows-portable.exe`：便携版，双击运行，不写注册表，需要系统已有 WebView2。
   发布说明来自仓库根目录的 `release-notes.md`，desktop-kit 会在后面附上各文件的 SHA256。
4. tag 与版本不一致、或任一门禁失败，工作流直接失败，不会发布。

应用内「检查更新」读的是最新的 Release，所以发布后已安装的用户就能看到新版本。

## 构建前

- [ ] `pnpm install --frozen-lockfile`
- [ ] `pnpm check`
- [ ] `pnpm lint`
- [ ] `pnpm test`
- [ ] `cargo fmt --check`
- [ ] `cargo clippy --all-targets --all-features -- -D warnings`
- [ ] `cargo test`
- [ ] `pnpm build`
- [ ] 检查 `src-tauri/tauri.conf.json` 版本和 identifier
- [ ] 检查 capability 没有 shell、任意 fs 或通配权限

## Windows 实机验收

- [ ] WebView2 缺失时安装/启动行为明确
- [ ] 首次启动创建独立应用数据目录
- [ ] 搜索、歌单、专辑和多平台 source 状态正确
- [ ] 试听、暂停、进度、音量和媒体键正常
- [ ] 下载、取消、失败、重试和临时文件清理正常
- [ ] 本地音乐扫描、分页、上传、删除和封面歌词正常
- [ ] Cookie 保存不回显、不进日志
- [ ] FFmpeg/ffprobe 存在和缺失都能降级
- [ ] 关闭窗口不残留后台进程
- [ ] 日志和诊断导出不含敏感信息

## 发布后

- [ ] 安装包可在干净 Windows 环境启动
- [ ] 记录版本、构建时间、Rust/Node/pnpm 版本
- [ ] 保存 CI、人工验收和平台验证报告
- [ ] 更新 `docs/音源与已知问题.md` 和 `docs/平台能力矩阵.md`

## 回滚

应用只读写自己的应用数据目录，因此回滚只需卸载当前安装包并删除应用数据目录。发布前保留安装包、构建日志和诊断日志；删除应用数据前由用户明确确认。
